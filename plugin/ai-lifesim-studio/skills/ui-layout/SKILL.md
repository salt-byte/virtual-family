## 生活模拟的界面骨架（新增：本项目已定，非原文）<!-- NEW(lifesim) -->
屏幕大部分是房子本身。底部一条：选中的人（名字、年龄、营生、正在做什么用一句话、状态用词不用条）和钱。
左上两个小按钮：夸、骂。
其余（商店、目标与收集、家谱、家具摆放、设置）都是弹出面板，关掉就回到房子。

## 为什么会「太 AI」
同一套默认审美：深色半透明圆角面板、细描边、无衬线字、文字按钮、没有图标、没有材质。和游戏世界的像素画没关系。

## 先列玩家要做的决定，再画界面

先读 [UI/UX 设计方法](references/ui-ux.md)（模块 8）：界面清单分高中低频、3–5 条关键动线、信息层级与反馈规范、剧情回顾和对话历史。
每一屏开工前先写三行（放进 `design/ui/<屏>.md`，几句话就够）：
- **这一屏玩家要做什么决定**：底部条 → 要不要先照顾这个人；商店面板 → 买什么、花多少；家具摆放 → 放哪间屋。界面上最大、最亮的东西必须是这个决定需要的信息，其他都让位。
- **控件的全部状态**：每个按钮 / 栏位写出默认、悬停、按下、禁用、选中、不可用的原因（钱不够时购买按钮灰掉并写「钱不够」，而不是点了没反应）。graveholme 升级面板没关挡住移动，就是没列「面板打开时其他输入怎样」。
- **弹出面板要求**：标题、关闭按钮、内容、操作按钮各在哪；打开时房子里的输入怎样；能不能 Esc 关闭；操作有没有快捷键。
写完再做视觉。这条来自 game-ui-design（MIT）的「先列玩家决定」，按我们的屏重写。

## 风格契约（和 art-direction 共用）
界面的底色、强调色、边框做法、字体、字号层级、图标风格，写进 `design/ART_DIRECTION.md` 第 4 节 HUD 信息层级旁的「界面风格契约」表；所有屏按它做，不各自发挥。做法来自 game-ui-design-workflow 的 style-contract 文件。

## 界面代码怎么组织（借 game-ui-ux 的四条，用自己的话）
- 锚点布局：每个面板相对视口的角 / 边定位，换分辨率不重排。
- 界面栈：打开的面板压栈，Esc 弹栈；栈不空时世界不接收输入（graveholme 的 `can_move()` 就是在查这个）。
- 事件驱动：HUD 只订阅状态变化（`GS.changed`），不每帧轮询。
- 键盘焦点：每个面板打开时有一个默认焦点，方向键能走完所有控件。

## 步骤
1. **观察参考作品**（在用户电脑上实机看，`computer-use` 只截图不提取素材）：底部条、弹出面板、菜单、商店、目标与收集页。每个界面记录：
   - 位置和占屏比例；头像在哪、多大
   - 边框做法（像素描边？九宫格贴图？有无圆角）
   - 配色（底色、强调色、稀有度颜色）
   - 字体（像素字？衬线？字号层级）
   - 哪些用图标代替文字
   - 动效（飘字、弹出、按钮按下）
2. 把观察写成 `references/<参考游戏>-ui-notes.md`，在确认点给用户看结论 + 一张我们的样式截图<!-- TODO(lifesim): 原文指向 producer 的「确认点 B」，本插件暂无对应技能 -->。
3. **实现**：
   - 边框用像素九宫格（自己画或 CC0 像素 UI 包），不用圆角矢量面板
   - 文字按钮换成图标 + 快捷键提示
   - 中文用像素字体或与画风相配的字体
   - 稀有度、状态用统一色板（见 `style-consistency`）
4. 截图对比参考作品的截图，用户确认后再改其余界面。
