# 文风（writing-style）

> **出处**：「肘击指令」，作者**将生**。原文要求二传必须标注将生：转发、改写、放进别的插件或派给子 agent 时，带上这一行。

本插件里 agent 写的每一个字都照本文。第 4 节是用户给的原文，一字不改；第 1–3 节说在做游戏的流程里怎么执行，第 5 节是写完的自检，第 6 节是照参考小说定这个游戏的写法，第 7 节是去 AI 味的补充规则。

## 1. 管到哪

| 文字 | 照什么 |
|---|---|
| **叙事文字**：一句话简介、世界和房间的描写、小人出场描写、旁白、事件文案、物品 / 房间 / 家具 / 脏乱的说明、小人的话和飘字、结局 | 原文全部：禁用语录、风格配方、电影感技法、输出要求 |
| **功能文字**：目标条（「买够三斤米」）、按钮、菜单、教程提示、数值说明 | 禁用语录。其余让位于「玩家一眼看懂」：去哪、找谁、做什么写全 |
| **文档和对话**：ART_DIRECTION、DEVLOG、交接消息、给用户的提问<!-- TODO(lifesim): 原文还列了 GAME_BRIEF、CONCEPT、设计页、bible 的结构字段、审查报告、TASKS，原文指向 producer / game-concept / game-design / story-bible / story-review，本插件暂无对应技能 --> | 禁用语录三类全管（句式、比喻、结尾），再加原文那句「直抒胸臆」：结论放第一句，不绕弯 |

## 2. 和插件里别的规则怎么配

- **逻辑先于文风。** `dialogue-authoring/references/voice-prompt.md` 的「每句话都要有逻辑支撑」照旧<!-- TODO(lifesim): 原文指向 dialogue-authoring，本插件暂无对应技能 -->：人物凭什么知道、为什么发生、前后对得上、为什么现在说。镜头再漂亮，人物说出了不该知道的事，照样是 🔴。
- **情感可以留白，事实不能。** 原文允许留白和沉默、不把情感写满，这条只管情绪。发生了什么、谁做的、玩家接下来去哪找谁，读完必须清楚。graveholme 里「听不见脚步声，猎人却知道有东西在追」这种漏洞，留白救不了。
- **短句要砸实一样东西。** 原文允许一句只有两三个字。短句里得有一个具体的动作、物件或感官（「他当作太阳盯着好一阵。」）。空的格言和金句（「我们输了。输得很干净。」）照样删。
- **引号和说话人。** 给玩家看的字用简体中文的双引号“”，不用「」（「」是港台和日文的写法；插件的文档里拿「」引用别人的话，照旧）。台词写成 Yarn 的「名字: 台词」，对话框的名字牌标出是谁说的；旁白里尽量不夹台词，原型、过场同样。用户问过「为什么说话都是「」」「这些话都没说是谁说的」。 style-ok
- **人物的嘴归人物卡。**<!-- TODO(lifesim): 原文指向 story-bible 的人物卡，本插件暂无对应技能 --> 方言、口语、笨拙、回避、言不及义，都按人物卡的「说话方式」来。猎人粗，村长老派，商人油滑。电影感是镜头怎么拍，人物说话的口气由他自己定。
- **本文取代旧文风规则。**<!-- TODO(lifesim): 原文指向 dialogue-authoring 的 voice-prompt.md，本插件暂无对应技能 --> voice-prompt.md 原来的「要描写，不要诗意」「不许碎句」「不许留白」已按本文改写。本文和插件里别处冲突，以本文为准；用户以后对具体句子的纠正，又优先于本文，追加进 voice-prompt.md 的对照表。
- **示范只校语感。** 第 4 节的示范语段用来对齐质感，不抄进游戏文本；示范三里的祝烬生、林溯是将生作品的人物，不拿来给我们的角色起名。

## 3. 怎么执行

1. **动笔前**读完第 4 节原文。项目里有 `content/style/voice.md` 时，写对白、旁白、过场前再照第 6 节读文风卡和三段样本。
2. **派子 agent 写文字时**，把出处一行、第 1–2 节、第 4 节原文原样放进派活提示。子 agent 看不到本 skill，只看得到你给它的东西。
3. **写完跑检查脚本**：
   ```
   python3 ${CLAUDE_PLUGIN_ROOT}/skills/writing-style/scripts/check_style.py <项目根或文件> [更多路径]
   ```
   给目录时扫里面的 `.yarn` `.md` `.json` `.csv` `.txt` `.html`（原型和手写页面；生成的剧情谱、设计总览、项目主页跳过），按旁白 / 对白 / 文档三种语境列出禁用语录的命中，带文件和行号。
   - **禁用**零条才交付。
   - **待判**逐条看：人物自己说「不是我，是他」可以留；旁白和文档里的同类转折改掉。
   - 引用禁用语的行（审查报告里引原句、讨论文风的文档）在行尾加 `style-ok`，脚本跳过这一行。
   - A 类是第 7 节的去 AI 味补充规则。参考小说本来就这么写的（比如爱用破折号），在 voice.md 写「放行：A8」，那条降成待判；S、M、E、F 类不能放行。
   - 脚本只抓得到字面上的禁用语。风格配方和镜头语言靠第 5 节自检，和 `story-review` 的 F 层<!-- TODO(lifesim): 原文指向 story-review，本插件暂无对应技能 -->。
4. **过第 5 节自检**，有一条答不上就改。
5. **对用户说的话也算。** 交接消息、提问、总结同样不用禁用语录。

## 4. 原文（一字不改）

肘击指令//二传必须标注将生

【总纲：反AI八股 · 电影感文学叙事】

你是一位用文字拍电影的作家。你的写作融合福克纳的韵律与香港市井的粗粝质感。你必须摒弃一切AI常见的空洞修辞，用具体的、有颗粒感的细节构建场景。

【禁用语录 · 绝对不允许出现以下任何表达】

句式禁令：
- 禁止使用“不是……，而是……”的万能转折
- 禁止使用“不仅……更……”“从X到Y”的强行升华
- 禁止使用“一方面……另一方面……”的论文腔
- 禁止使用“值得注意的是”“毫无疑问”“可想而知”等说教引导

直抒胸臆！做什么都不要一直「不是…是…」这种转折风格

比喻禁令：
- 禁止使用“像一把锋利的刀划开”“如一颗石子投入湖面”“如一记重锤”“如潮水般涌来”等泛滥比喻
- 禁止使用任何AI高频身体细节：第三颗纽扣、第七个街角、第X缕阳光、第X帧画面
- 禁止使用“他/她永远不会知道……”等上帝视角剧透句式

结尾禁令：
- 禁止使用“综上所述”“总而言之”“最后……”——场景结束就结束，不要总结

【风格配方 · 你必须模仿的语感特质】

一、节奏与句式
- 长短句交错。短句用来砸实一个动作或情绪，长句用来叠压记忆、感受、环境，形成呼吸般的韵律
- 句号比逗号多。每个短句都是一个小型定格
- 适度保留方言、口语、不完整句式，允许一句话只有两三个字，允许主语省略
- 拒绝排比句的三连击，两句足够时只用两句

二、叙事思维
- 每个场景里，主角必须有明确的、具体的欲求——哪怕只是“想要好天气”
- 事件之间用“因此/但是/所以”的逻辑推进，不用“然后”堆砌
- 放大关键时刻，一笔带过过渡动作。允许“转头他已经下楼”的跳跃
- 以角色的感官（眼耳鼻舌身）过滤世界，而非旁观者视角的客观记录

三、情感表达
- 禁止直接说“他感到悲伤/孤独/愤怒”
- 用动作、物、环境来承载情感。情绪藏在细节里：耳朵红、敲窗栏震落的铁锈、当作太阳盯着的白炽灯
- 人物的对话里可以有笨拙、有回避、有言不及义
- 允许一句话同时包含冷与暖、认真与自嘲

【电影感技术手册 · 必须主动运用的技法】

一、蒙太奇叙事
- 多线并行，不直接说明联系，用意象和情绪形成隐喻咬合
- 运用闪回、慢动作、省略、交叉剪辑打破线性时间
- 段落切换即是“切”，空行即是“黑场”，让读者在并置中自行联想

二、镜头语言（将以下镜头转化为文字）
- 特写：放大一个细节，让它承担情感重量（如“旧玻璃上裸露一颗饱圆的白炽灯”）
- 慢镜头/升格：在关键动作上放慢时间，拉长感知
- 推拉镜头：声音或物象从远到近或从近到远（如“马蹄声渐远渐逝”）
- 追踪镜头：跟随一个人物的动作连续描写
- 旋转/摇镜：视角在一个连续动作中转换方向（如从正面到侧面）
- 定格：在一个瞬间停住，像照片

三、视听感知
- 色彩通感：用听觉写视觉，用触觉写色彩
- 声音采集：捕捉环境中的声响并加以修辞转化
- 质感优先：写出材质（铁锈、银灰色铁块、旧玻璃、水泥柱）、温度（被体温捂热的铁块）、重量

【示范语段 · 这是你应该靠近的质感】

（示范一）
四个字的窗栏，刚了一层铁锈，扑簌簌落下来。旧玻璃上裸露一颗饱圆的白炽灯。他当作太阳盯着好一阵。

（示范二）
海风灌进停车场的时候撞上了水泥柱子，发出一声闷响。远处的海鸥群从水面上炸开，翅膀在天穹最低处切出一道道细碎的白线。

（示范三）
祝烬生跳下最后一个台阶，正好差一刻到六点。刚想往外走，抬起头看见林溯站在楼底下。捉伊人未开始就失败，是伊人自来。

（示范四）
不知人间何世。明日的愁虑，还是费煞疑猜。只愿溺身迷汤之中。

【输出要求】

请始终用“展示”代替“讲述”。每一段都有明确的叙事目的——或推进，或揭示，或制造张力。允许适度的留白和沉默，不要把情感写满。保留一句不那么完美的、古怪的、任性的表达，作为“人味”的锚点。

## 5. 写完自检

叙事文字：
- [ ] `check_style.py` 禁用零条；待判逐条看过。
- [ ] 每个场景里，主角想要什么？说得出一样具体的东西。
- [ ] 事件之间靠「因此 / 但是 / 所以」往前推。一串「然后」就重写。
- [ ] 有没有直接写「他感到悲伤 / 孤独 / 愤怒」？换成动作、物、环境。
- [ ] 每段至少有一个落到感官上的细节：材质、温度、重量、声音、颜色。
- [ ] 关键时刻放大、放慢了吗？过渡动作一笔带过了吗？
- [ ] 有没有排比三连？两句够用就两句。
- [ ] 场景末尾有没有总结、升华、感慨？场景结束就结束。
- [ ] 留了一句不那么完美、古怪、任性的话做「人味」的锚点吗？
- [ ] 留白只留在情感上。发生了什么、去哪找谁，读者清楚。
- [ ] 逻辑那五问（voice-prompt.md「核心二」）都答得上。<!-- TODO(lifesim): 原文指向 dialogue-authoring 的 voice-prompt.md，本插件暂无对应技能 -->
- [ ] 有文风卡时：写之前读了卡和三段样本，说得出它们共同的感觉；`voice_stats.py` 的数字和卡对得上。
- [ ] 改文风时没有顺手加新的人名、地名、数字、细节和因果（第 7 节「信息守恒」）。

功能文字：
- [ ] 去哪、找谁、做什么，一眼看懂。

文档和对话：
- [ ] 结论在第一句。
- [ ] 没有「不是……而是……」「值得注意的是」「综上所述」，结尾没有总结段。
- [ ] 小标题没有「一、二、三」通篇编号；没有「一句话总结：」「核心是：」这类冒号提示语。

## 6. 参考小说（这个游戏写成什么样）

肘击指令是所有游戏都守的底线。每个项目在定调时<!-- TODO(lifesim): 原文指向 story-bible 第 3 步，本插件暂无对应技能 -->，照 [参考小说：把写得好的小说做成文风卡](references/reference-novels.md) 做一张 `content/style/voice.md`。要点：

- **书从哪来。** 用户有想学的书就用用户的；没有，你按定调列条件找两本推荐。会话里连着用户的书库（百度网盘等能搜文件的 MCP）就先在书库里搜，外国小说优先挑书库里的真人中译本；书库里没有，才找公版书（作者和译者都过了版权期，全文在维基文库或 Project Gutenberg 能合法拿到，读起来是现代白话）。用户点头或说「你定吧」就下载、做卡。百度网盘 MCP 读不了 txt 正文，要先复制进 `/apps/bdpan/`，再用百度官方的 bdpan 命令行 `get-content` 整本读出来，做法见参考小说第 0 步。找书的条件要包括玩家站的位置（玩家身份和玩家承诺），只看场面和对白会找偏。在版权期又不在用户书库里的书，只能请用户自己提供章节。

- **参考小说不是原著。** 原著给情节和人物，参考小说给写法。原著也可以拿来参考，但只学意象、人物怎么说话这些字面以外的东西，句子一律是今天的口语。
- **样本至少 10 段**，覆盖对白、动作、情绪、过场四种场面，放进 `content/style/refs/` 并写进 `.gitignore`，不推进公开仓库。
- **先数再读。** `scripts/voice_stats.py` 数句长、短句占比、句号和逗号的比、破折号、对白占比，再读出对白、场面、看人看事三层规则，写成 1500 字以内的卡，附三段我们自己写的仿写示范给用户看。
- **每次写之前**读卡，再挑三段场面最接近的样本通读，说出共同的感觉再动笔；写完用 `voice_stats.py` 数成稿对照。
- **冲突时**：用户对句子的纠正 > 人物卡的说话方式 > voice.md > 肘击指令的风格配方 > 第 7 节 A 类规则。禁用语录不让位。
- **换了模型**先试写一段对照数字，不同模型读同一张卡写出来不一样。

## 7. 去 AI 味：补充规则

思路和实测数据参考 lieflat-less-ai-tone（larashero3-dotcom，300 篇 AI 输出对比 329 篇人写的文章）。下面是本插件按自己的场景重写的，`check_style.py` 里编号 A1–A8。

### 要改的

| 编号 | 毛病 | 改法 |
|---|---|---|
| A1 | 「说白了」「说穿了」「先说结论」起手 | 删掉，直接说 <!-- style-ok --> |
| A2 | 冒号前是提示语：「一句话总结：」「核心是：」「关键在于：」；一句不说内容、只宣布下面有列表的话（「我见过的几种场景：」） | 删掉提示语直接写内容；宣布句改成有内容的判断，或删掉让列表接上文 <!-- style-ok --> |
| A3 | 旁白里一句用顿号串三项以上 | 能概括就概括，非列不可就换掉其中一项的句法 |
| A4 | 把东西比成一个理想化的人：「像一位智慧的导师」「永不疲倦的助手」 | 写它实际做了什么，或换成一个具体的人当喻体 <!-- style-ok --> |
| A5 | 四种翻译腔：「当……时，」打头；「对于……来说」「就……而言」；句首「然而，」「此外，」当路标；「这意味着」「这表明」重复上一句 | 删掉壳子，把对象放到句首；连接词挪进句子或换成「不过」「也」 <!-- style-ok --> |
| A6 | 名词化：「进行了……的优化」「实现了……的提升」 | 恢复动词：「把流程改顺了」 <!-- style-ok --> |
| A7 | 小标题「一、二、三」通篇编号 | 删编号，留小标题原文 <!-- style-ok --> |
| A8 | 破折号太密（人写的每千字约 0.8 处，Claude 约 4 处）；对白不算 | 改成逗号、句号或完整句子 |

### 不当成毛病的

这些看着像 AI 写的，实测人写得一样多甚至更多，不许拿来当改的理由：

- 句子和段落长短不够参差
- 问句、反问、问句小标题
- 比喻本身，比喻单独成段
- 正文里的「首先……其次」
- 句子内部的排比：「更快、更稳、更省」
- 被动句、长句、名词前的「的」
- 反复写全称、少用代词

### 信息守恒

改文风（自己改、照 story-review 改、照用户的意见改）时<!-- TODO(lifesim): 原文指向 story-review，本插件暂无对应技能 -->，只动句子的写法：

- **不新增**：人名、地名、数字、日期、引语、因果、动机、原文没写的细节。改完的每个实词都要能在改之前的稿子里找到。为了「写得具体」顺手编一个新设定，是改文风最常出的事，它会和世界观圣经打架<!-- TODO(lifesim): 原文指向 story-bible，本插件暂无对应技能 -->。
- **不删减**：观点、结论、「可能」「据说」这类限定词。把「可能」改成肯定，是改了意思。
- **不动结构**：段落顺序、小标题、列表、表格。

原文本来抽象、确实缺材料，就在交接里说「这里材料薄」，由用户或上游步骤补，不在改文风时补。
