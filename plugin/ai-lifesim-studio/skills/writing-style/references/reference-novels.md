# 参考小说：把写得好的小说做成文风卡

肘击指令管的是所有文字都要守的底线，参考小说管的是这个游戏具体写成什么样。每个项目都做一张文风卡 `content/style/voice.md`：用户有想学的书就用用户的；没有，就由你按定调去找、推荐、下载、拆，当场把文风定下来。之后每次写对白、旁白、过场都先读这张卡。

做法参考了 writing-dna-skill（larashero3-dotcom）的蒸馏流程：先拆成规则，写之前再回读原文校语感。本文按做游戏的需要重写，只留对白、旁白用得上的部分。

## 什么时候做

- **定调时**<!-- TODO(lifesim): 原文指向 story-bible 第 3 步，本插件暂无对应技能 -->：两道定调题答完，口气定了，就照下面第 0 步找书、推荐，用户点头后做卡。卡做完再写 bible.md，世界观和人物的描写段落也照卡写<!-- TODO(lifesim): 原文指向 story-bible，本插件暂无对应技能 -->。
- 用户说「文笔不行」「像 AI 写的」「没有小说那种感觉」时，回到这里重找或重做。
- 用户随时加一本或换一本。换了就重做卡，旧卡写进卡末的「版本」。重做之前先把整张旧卡复制到 `refs/_old/voice_<日期>.md`，旧样本也挪进 `refs/_old/`：用户常会觉得新卡不如旧卡，要拿出来对比。

做卡比较费时（读、挑、翻、拆，十几分钟），派一个子 agent 去做，把本文、writing-style 第 2、4、7 节、定调结果和 GAME_BRIEF 一起放进派活提示。

## 0. 找书

用户给了书就跳过这一步。用户说「你找」「你定吧」或没提，就由你找：

1. **按定调和 GAME_BRIEF 列条件。** 把口气翻成找书的条件，至少四条：
   - 场面要像：故事开头是什么样的场面（一家人的日常、行军、宫廷、市井）
   - 走向要像：悲剧往下坠、成长往上走、群像散开还是收拢
   - 嘴要像：对白多不多、谁嘴碎、谁不说话
   - 玩家站的位置要像：玩家身份和玩家承诺里那件事，书里得有人站在同样的位置上（学徒、旁观者、知道结局的人）
   例（亚瑟王，温情里带刺，前两章一家人的日常，悲剧一章比一章重；玩家是梅林的学徒，能在水面上看见家里人的将来，改不了结局）：一家人有挖苦也有笨拙的照顾；一个学法术的孩子跟着话少的师父；有人早就知道这家人的结局，结局还是照样来了。
   只照前三条找，找到的是《远大前程》：家里的对白很像，可是没有法术，也没有「看见了却改不了」，用户看了说不贴。
2. **挑候选。** 想五六本贴条件的书，再按下面的顺序找全文，找到的留下：
   - **用户的书库。** 会话里连着能搜文件的 MCP（百度网盘 `mcp__baidu-pan__*`，或别的网盘、文档库），先按书名和作者搜。用户书库里的书算用户自己提供的，在版权期的也能用，只在本地分析（见第 7 节）。外国小说优先挑书库里的真人中译本。同一本搜到几个版本时看大小：大一半左右多半只是编码不同（同一段中文，UTF-8 每字 3 字节，GBK 每字 2 字节），差得更多或更少的才可能是不同译本或删节本。译本到底是哪个，读出正文看开头和末尾的译后记再定。
   - **公版站。** 书库里没有，就只挑公版：作者和译者都已过版权期（中国大陆是去世后满 50 年）。中文先查维基文库，英文查 Project Gutenberg。在版权期的书不从网上抓。
   - 读起来是现代白话：半文半白、1930 年代的硬译不选。
   - 和原著不是同一部，题材也不必相同。学的是写法，亚瑟王可以学狄更斯。
3. **推荐两本给用户。** 每本一句话说学什么（对白 / 场面 / 过场）、一句话说为什么贴这个游戏的定调，再说全文从哪来（书库路径、哪个译本，或公版站）。用户点头再下载；用户说「你定吧」就用你推荐的两本，写进交接的「替你定的」。
4. **下载。** 全文放进 `content/style/refs/_source/`，先确认 `content/style/refs/` 已经写进 `.gitignore`。
   - 公版站：Gutenberg 的纯文本地址是 `https://www.gutenberg.org/cache/epub/<编号>/pg<编号>.txt`。
   - 书库：见下面「从百度网盘拿书」。
5. **转成 UTF-8。** 书库里的老 txt 多半是 GBK 编码。先试 UTF-8 读，读出乱码就用 `iconv -f GB18030 -t UTF-8` 转一份再用（用下面 `bdpan get-content` 读出来的已经是 UTF-8）。看开头和末尾几百字里的译者、译后记，和推荐时说的对不上就告诉用户。

例（亚瑟王项目，2026-11-11 换的）：从用户书库挑了勒古恩《地海巫师》（台湾蔡美玲译本，约 11 万字），学师徒对白、法术的分量和学徒的视角；马尔克斯《百年孤独》（1984 年上海译文黄锦炎等译本，约 26 万字），学一家几代人怎么被早就写好的结局一步步追上，还有「多年以后」这种先看见将来的句子。《百年孤独》对白少，家里的对白另找样本补。原来用的《远大前程》和契诃夫（Gutenberg 公版英文，自己翻）不贴，换掉了。

### 从百度网盘拿书

2026-11-11 实测，书库里的书多半是 txt。百度网盘 MCP 读不了 txt 正文：

- 搜索结果只有路径、大小和预览链接，没有正文。预览链接要网盘 app 的登录态，直接取返回 403。
- MCP 的正文读取（`file_content_create`）只认 doc、docx、pdf、ppt、xls，txt 报 40104。
- MCP 搜索一次能返回十几万字的 JSON（每条带三个缩略图链接），会被存成文件。限定 `dir`，用 Bash 里的 python 只取 `path`、`size`、`fsid` 三个字段看。

能读 txt 的是百度官方的 bdpan 命令行。它只能碰「我的应用数据/bdpan」（`/apps/bdpan/`）里的文件，所以分两步：

1. **复制。** 用户点头后，用 MCP 的 `file_copy` 把选中的书复制进 `/apps/bdpan/refs/`，改成短名字（`地海巫师.txt`）。这会在用户网盘里多一份，推荐时先说明。
2. **读。** `bdpan get-content <fsid> --json`，fsid 用 `bdpan ls refs --json` 查。txt 是同步读，直接返回整本正文，已经转好 UTF-8：实测 11 万字、26 万字的书都一次拿全，没有像说明里写的那样超过 2 万字就改给下载链接。把 `data[0].content` 写进 `content/style/refs/_source/<书名>.txt`。要是哪天返回的是 `url` 不是 `content`，就在 2 小时内用那个链接下载。

本机还没有 bdpan 时，先停下来告诉用户要装，用户同意再装（实测的坑都在括号里）：

1. 装 skill：`npx --yes skills add https://github.com/baidu-netdisk/bdpan-storage/skills --skill baidu-drive --agent claude-code --global --yes`。（不带 `--agent` 和最后的 `--yes` 会停在交互菜单上。用户走代理连不上 npm 官方源时，加 `--registry=https://registry.npmmirror.com`。）
2. 装命令行：`bash ~/.claude/skills/baidu-drive/scripts/install.sh --yes`，装进 `~/.local/bin`，当前终端要先 `export PATH="$HOME/.local/bin:$PATH"`。
3. 登录：在用户的终端里跑 `login.sh --continue-task`。它先要用户确认百度的安全须知，再给一个授权链接：用户在浏览器登录、点授权，把 32 位授权码贴回终端。这两步都让用户自己做，授权码不要经过你。（授权页左边登录框空白时，多半是代理挡了百度的扫码组件：让用户刷新、给 baidu.com 走直连，或者把链接里的 `qrcode=1` 去掉改用账号密码登录。）

用户不想装 bdpan，就请用户在百度网盘 app 里下载那一本，告诉你文件在哪，你复制进 `_source/`。

读完以后，`/apps/bdpan/refs/` 里的副本可以删，删之前问用户。

doc、docx、pdf 格式的书用 MCP 的 `file_content_create` 就能读，不用 bdpan：一次最多 100 页，每天限 20 个文件、200 页、100 万字。

## 参考小说和原著不是一回事

- **原著**给情节、人物、世界。
- **参考小说**给写法：句子多长、对白怎么来回、一场戏怎么开怎么收。

原著也可以拿来当参考，但只学字面以外的东西：意象、人物各自怎么说话、叙述离人物多近。句子一律是今天的口语，不照原著的文言或半文半白写（story-bible 3.2 的规定<!-- TODO(lifesim): 原文指向 story-bible，本插件暂无对应技能 -->）。

## 外国小说

用户想学外国小说时，优先用好的中译本，因为语言那一层要学的是中文。

- **用户有中译本**（电子书、纸书拍照）：照下面第 1 步收样本，最可靠。
- **用户书库里有中译本**：照第 0 步下载，当作用户给的书，不用自己翻。
- **由你去网上找时**：只找公版（见第 0 步）。还在版权期的书和译本不从网上抓，那是盗版。公版中译本网上大多没收（维基文库只有零星几部，而且多是 1930 年代的硬译，读起来拗口，不用）。这时用公版英文原文（Project Gutenberg），自己翻：
  - 每段样本英中对照放一个文件：先英文原文，再「## 中译」。
  - 照原文断句翻：一句英文对一句中文，长句可以拆，不并句；不加形容词，不加解释，不顺手润色；对白用“”，人物的粗、躲、答非所问都留着。
  - 译文先过 `check_style.py`，禁用零条才算样本。
  - 长度按英文词数算：每段 400 到 1200 词。
  - 原文本来就有「不是 X 而是 Y」这类禁用句式时，译文换个说法，意思不变；照原文硬翻会撞上禁用。 <!-- style-ok -->
  - 对白、场面、看人看事这三层从英文原文学。语言那一层的数字来自我们的译文：一句对一句的译法会把英文的句长和逗号带进来，所以句长、句号和逗号的比不能照抄，只借短句占比、破折号和不同场面之间的差别（比如对白戏句子短、过场句子长），卡开头写明这一点。译文是模型写的，可能带着 AI 腔，所以语言那一层只当参考，用户以后给了真人中译本就换掉。

## 1. 收样本

- 用户给的书：用户给文件、贴文字或给书名和章节。你找的书：从第 0 步下载的全文里挑段落。样本放进 `content/style/refs/`，并把这个目录写进项目的 `.gitignore`。项目仓库多半是公开的，别人的小说不能推上去。
- **量**：至少 10 段，每段 500 到 2000 字，给整章更好。尽量覆盖四种场面：对白多的、动作和打斗、安静的情绪戏、交代过场。只有一两段也能做，卡里写明「样本少，只校语感」。
- **一本还是两本**：一般最多两本。两本写法打架时问用户各学什么，比如对白学 A、旁白学 B。按场面分好工、各管一块不重叠时可以多于两本，卡开头写清哪本管哪种场面。例（亚瑟王）：家里的戏学狄更斯和契诃夫，看水面学《百年孤独》，师父和法术学《地海巫师》。只换书、不分工，用户读后觉得新卡不如旧卡。
- 每段在 `refs/index.md` 记一行：出处（书名、章）、场面类型（对白 / 动作 / 情绪 / 过场）、字数。样本文件开头的出处、场面、字数写成表格，`voice_stats.py` 不数表格，写成普通文字会被算进样本里。

## 2. 拆

四层，先数再读。

**语言**：先跑数字：

```
python3 ${CLAUDE_PLUGIN_ROOT}/skills/writing-style/scripts/voice_stats.py content/style/refs/
```

记下句长、短句和长句的占比、句号和逗号的比、破折号和冒号每千字几处、对白占比、段长。再读，找常用词、从来不用的词，以及方言和口语怎么混。

**对白**：一句台词多长，谁打断谁，人物怎么回避、怎么答非所问，台词前后有没有动作，用不用「他说」。

**场面**：一场戏从哪里开（动作、环境还是一句台词），中间怎么切，停在哪里（一个动作、一样东西还是一句话），大概多长。

**看人看事**：叙述贴着谁看，对人物狠不狠，笑从哪里来，什么事一笔带过、什么事放慢。

每层写三到五条照着就能写的规则，每条后面附一句原文短引作证，标出处。短引一条不超过两句。

## 3. 写文风卡

`content/style/voice.md`，1500 字以内。超了说明没拆干净，只是在复述。

```markdown
# 文风卡

参考：〈书名〉，〈作者〉（样本 N 段，约 X 字）
学什么：对白 / 旁白 / 两样都学

## 语言
| 指标 | 参考小说 | 写的时候 |
|---|---|---|
| 句长 | 14.2 | 12–18 |
| 短句占比 | 52% | 不低于 40% |
| …… | | |
- 规则……（短引，出处）

## 对白
## 场面
## 看人看事

## 不学的
- 原著和参考书里的文言、半文半白
- 参考书的情节、人名、原句

## 仿写示范
用我们自己的人物和地点各写一段，每段不超过 150 字：对白一段、动作一段、情绪一段。对白那段也要有环境：开头一个声音、一样温度或材质，人物停嘴的地方切一次环境。只写台词加动作，用户读了嫌「只是对话」。

## 放行
- 放行：A8（参考书本来就爱用破折号时才写这一行；只能放行 A 类规则）

## 版本
- 2026-11-11 初版：参考〈书名〉
```

仿写示范先过一遍 writing-style 第 2 节「情感可以留白，事实不能」：只读这一段的人，能说出东西在谁手里、事情从哪来、人物为什么这么做吗？省略学的是不写情绪和感慨，事情本身要交代清楚。学契诃夫的省略最容易把事实也省掉，比如人物的剑去哪了没交代，读者就看不懂这场在吵什么。

写完给用户看「仿写示范」三段，问像不像他心里想要的。不像就问差在哪，回到第 2 步补。

## 4. 每次写之前

1. 读 `voice.md`。
2. 从 `refs/` 挑三段和这场戏场面类型最接近的，通读，用一句话说出它们共同的感觉，再动笔。只读卡学不到节奏，句子的呼吸只有原文里才有。
3. 派子 agent 写时，把 `voice.md` 和这三段一起放进派活提示。
4. 写完跑 `voice_stats.py` 数成稿，和卡里「写的时候」那一栏对照，差得多就改。

## 5. 冲突时听谁的

1. 用户对具体句子的纠正
2. 人物卡的「说话方式」
3. `voice.md`
4. 肘击指令的风格配方
5. 第 7 节的 A 类去 AI 味规则（参考书本来这么写的，在卡里「放行」）

肘击指令的禁用语录（S、M、E、F 类）不让位：参考书里有，我们也不用。

## 6. 换模型以后

文风卡是写给模型看的规则。不同模型读同一张卡，写出来也不一样，比如 Claude 爱用破折号，GPT 几乎不用。换模型后先用同一场戏试写一段，跑 `voice_stats.py` 和卡对照。哪项差得多，就在卡里给这个模型加一条针对的限制，标上模型名。

## 7. 版权

样本只用来分析，不进游戏文本，也不推进公开仓库。卡里的原文短引一条不超过两句。仿写示范和游戏里的文字都是我们自己写的。
