# 房间与固定物件（places-and-props）

房子是小人能做什么事的前提。《起家》的教训：玩家嫌「场景太小」，真正嫌的是**事情少**。地方多了，能在那儿做的事跟着多，小人才显得在过日子。所以排房子和排动作是一件事，这个技能做完，接着用 `action-authoring` 给每处配事。

## 数据长什么样

`game/packs/<id>/rooms.json`，每处一行：

```json
{"id": "yard", "name": "院子", "w": 17, "h": 7, "x": 7, "y": 7, "built": true, "build_cost": 0, "outdoor": true,
 "props": [{"type": "millstone", "x": 1, "y": 1}, {"type": "grape_trellis", "x": 12, "y": 3}]}
```

- `x`、`y`、`w`、`h` 以格为单位。要么每处都写 `x`/`y`，要么都不写（不写就按旧的单行排法），不能重叠。
- `built: false` 的地方画成虚线框，玩家花 `build_cost` 加盖。
- `outdoor` 决定能放哪些家具（物件的室内外要对得上）。
- 列表里**第一处室内房间是入口**：新人在那儿出现，画面打开时也停在那儿。
- `props` 是这处的固定物件，坐标相对房间左上角。开局就盖好的房间在第一次领养时放上；后盖的房间在加盖那一刻放上。

固定物件在 `objects.json` 里写 `"fixed": true`、`"price": 0`。它们是房子的一部分：商店里没有，玩家买不了、挪不动、卖不掉，也不算进「家具件数」类目标。

## 怎么排

1. **先定量**。《起家》定的是 14 处：开局盖好 8 处，6 处待加盖。少于 10 处，画面容易显得空。待加盖的几处价钱拉开（400 到 1200），玩家一眼看得到往哪儿扩。
2. **画网格草图**。屋里的排一行，院子、井台这些屋外的排下面，大门口放最下面。整片比一屏大没关系，画面能拖动、滚轮缩放；小于一屏会自动居中铺满。
3. **已有的 id 别改**。存档和测试都认 id，改名会让旧存档对不上。要扩就加新 id，旧的保留尺寸或只放大。
4. **每处配固定物件**。挑这处最有代表性的一两样：堂屋的饭桌、供桌，柴房的柴垛，井台的井。一样固定物件带两三件事（见 `action-authoring`）。
5. **核对事情够不够**。开局盖好的每处至少 3 件事能做，后盖的每处至少 2 件。数法：动作的 `rooms` 里写了这处，或者动作用的物件就放在这处。

## 旧存档

内核读档时自己补：包里新增的「开局就盖好」的房间补成已盖；已盖房间缺的固定物件，放得下就放，放不下（被玩家家具挡住）就跳过，不报错。所以改房子不用写迁移，但要在测试里用一个旧存档验证一遍。

## 验收

- `./game/tests/run.sh places`、`./game/tests/run.sh packs_both` 全过。其中 `test_qijia_every_built_room_has_things_to_do` 和 `test_qijia_rooms_built_later_have_things_to_do` 检查第 5 条。
- 校验器报错的格式是 `rooms.json: <房间 id>: props #i: …`，照着改。常见错误：固定物件超出房间、和开局家具重叠、室内物件放到了屋外、把非固定物件写进 `props`、把固定物件写进 `start_objects`。
- 再走一遍 `pack-verification`。

## 别做的

- 别为了「看着大」只放大房间面积：空地多、事情少，玩家照样觉得小。
- 别把固定物件做成可买的：它们是这处地方的身份，能卖掉的话，这处地方就空了。
