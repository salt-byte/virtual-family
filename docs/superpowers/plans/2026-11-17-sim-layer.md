# 模拟层（第 0 期 + 第 1 期的无画面部分）Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 一个不依赖画面的家庭生活模拟内核，在命令行里能跑完"领养一个人 → 自己过日子、生病、不开心 → 挣钱花钱 → 收拾、摆家具、加盖 → 媒人介绍成亲 → 老去"这一整圈，并带两个主题包（现代试验包、《起家》第 1 期内容）。

**Architecture:** Godot 项目 `game/`。`game/kernel/sim/` 是一组纯逻辑类（`RefCounted`，不继承 `Node`），顶层是 `World`：持有全部状态，`advance(seconds)` 以 60 秒为一步推进，`command(dict)` 接收玩家指令，`drain_events()` 向外吐事件。各系统是独立文件里的静态函数，由 `World` 按固定顺序调用。主题包是 `game/packs/<id>/` 下的一组 JSON，由 `Pack` 读入并校验。

**Tech Stack:** Godot 4.7.2、GDScript、JSON。测试用自带的最小测试运行器（不引入第三方插件），命令行 `godot --headless` 运行。

**Spec:** `docs/superpowers/specs/2026-11-17-lifesim-kernel-design.md`（执行者两份都要读）

**不在本计划内：** 画面层（下一份计划）、生育和继承（第 2 期）、家业阶梯/门第/四条营生路线及其关卡、季节结算、产业、风险（第 3 期）、事件表（第 4 期）。

## Global Constraints

- Godot 4.7.2，GDScript；`game/kernel/sim/` 下的类一律 `extends RefCounted`，不得引用 `Node`、场景树、`Input`、`Time.get_*_from_system`
- `game/kernel/` 下任何文件不得出现主题包的 id 或题材专用词（"科举""侯府""灶台""fridge"等）；内核只认"状态条、行为、物件、营生、房间、杂务、病、掉落物、目标"这些通用概念
- 所有随机都走 `SimRng`，同一种子、同一串指令必须得到同一结果
- 所有时间由外部传入（`World.set_time`），内核不读系统时钟
- 金币是整数，永不为负
- 默认值照设计文档：`hours_per_year = 2.0`，`offline_cap_hours = 48`；离线时照看不周不致死，寿终可以
- 每次改内核，`_smoke` 和 `qijia` 两个主题包的测试都要过
- 不搬参考游戏的任何名字、文案、图标；《起家》主题包文案全部原创
- 提交信息末尾加 `Co-Authored-By: Claude Fable 5.2 <noreply@anthropic.com>`；只在本地提交，不推送

## Review Focus

1. **系统时钟倒退或离开时间为负**（玩家改时钟、换时区）：`catch_up` 按 0 处理，不崩、不倒流。→ Task 13
2. **存档损坏或版本不认识**：读档返回错误而不是崩溃，原文件不被覆盖。→ Task 12
3. **主题包填错**（行为引用了不存在的物件或状态条、等级表为空）：`Pack.errors` 指出文件名和条目 id，`World` 拒绝启动。→ Task 2
4. **拖动的边界情况**：拖到别人正在用的物件、拖幼儿去干成人的事、拖一个已去世的人：指令返回 `ok=false` 和原因，状态不变。→ Task 5
5. **物件在使用中被卖掉或挪走**：正在用它的人的行为被取消，不留悬空引用。→ Task 9

  - `NeedsSystem.step(world: World, dt: float)`
  - `class_name TestKit`：`static func world(pack_id := "_smoke", seed := 1) -> World`（时间设为本地正午：`set_time(1767268800, 0)`）；`static func adult(w: World, age := 25.0) -> Person`（造一个状态条取 `start`、`lifespan = 70` 的成年人加入并把 `phase` 置为 `"living"`）

**规则：**
- `advance` 把传入秒数累进余量，每满 60 秒走一步；每步 `now += 60`，再依次调各系统（本任务只有 `NeedsSystem`，后续任务往后加，顺序见 Task 14 的汇总）
- 状态条每步减 `drain_per_hour / 60`，夹在 0..100；某条为 0 时按 `when_empty` 扣另一条
- `world.offline == true` 时，所有状态条不低于 `offline_need_floor`
- 年岁每步加 `60 / (hours_per_year * 3600)`
- `vital_need` 为 0（仅在线时可能）→ 去世，`cause = "neglect"`；`age >= lifespan` → 去世，`cause = "old_age"`（离线也生效）
- 去世：`alive = false`，清空 `current`，发 `person_died`；没有在世的人且 `phase == "living"` → `phase = "over"`，发 `game_over`

  - `AutonomySystem.can_do(world: World, p: Person, action_id: String, object_uid: int) -> String`（可做返回 `""`，否则返回原因：`"stage"` `"busy"` `"no_stock"` `"wrong_track"` `"requires"` `"no_object"` `"dead"`）
  - `AutonomySystem.start(world: World, p: Person, action_id: String, object_uid: int, target_uid := -1)`、`AutonomySystem.cancel(world: World, p: Person)`

**规则：**
- 闲着的人（`current` 为空、在世、非 baby）每步挑一次。打分：

```gdscript
# deficit = 100 - 当前值；每条状态的贡献不超过缺口
var gain := 0.0
for n in action.needs: gain += min(max(action.needs[n], 0.0), 100.0 - p.needs[n]) * (100.0 - p.needs[n]) / 100.0
var score := (float(action.get("base", 0)) + gain) * p.habits.get(action.id, 1.0)
for t in action.get("tags", []):
    if t in p.likes: score *= 1.5
    if t in p.dislikes: score *= 0.5
if action.has("hours") and not _in_hours(world.local_hour(), action.hours): score *= 0.1
```
  `hours` 的起点大于终点表示跨午夜。得分 ≤ 0 的不进候选。取分数最高的三个，按分数作权重随机挑一个。没有候选就闲一步。
- 可做的条件：年龄阶段在 `stages` 里；需要物件时屋里有这类物件且没被别人占用；`consumes` 的库存够；`work.track` 等于此人的 `track`；`requires.sick` 与是否有病相符；`requires.need_below` 满足
- 开始：`consumes` 立刻扣库存；占用物件；发 `action_started`
- 进行中：每步把 `needs` 效果按 `60 / (duration_min*60)` 的比例加到状态条上，`remaining_s -= 60`
- 结束（`remaining_s <= 0`）：清空 `current`，记 `last_action` 和 `last_action_t`，发 `action_finished`。（`work`、`mess`、`cleans`、`picks` 的结算由后续任务在这里接上）

  - 本任务的指令：`{type:"drag", person, object}`（可选 `action`；不给则取该物件类型上此人可做的第一条行为）、`{type:"praise", person}`、`{type:"scold", person}`

- 夸烦了：`praise_window_min` 分钟内已被夸过 `praise_annoy_count` 次，再夸 → `ok = false`、`error = "annoyed"`，习惯权重和状态条都不变。批评不受此限

**Interfaces:**
- Produces:
  - `World.candidate: Dictionary`（当前候选人，`Person.to_dict()` 的形状）、`World.proposals: Array[Dictionary]`（`{id, person: Dictionary, savings: int, expires_at: int}`）、`World.married: bool`、`World.next_proposal_at: int`
  - `FamilySystem.make_person(world, age_range: Array) -> Person`：从 `names.json` 抽姓名和性别；`track` 随机一条营生，`level` 0；`aptitude` 在 `[0.6, 1.4]`；`likes`、`dislikes` 各从 `tags` 抽 0–2 个且不重复；`lifespan` 在 `lifespan` 区间；状态条取 `start`
  - `FamilySystem.step(world, dt)`
  - 指令 `{type:"reroll"}`（换一位候选人，旧的不再回来）、`{type:"adopt"}`（候选人入住，`money = start_money`，`phase = "living"`，`next_proposal_at = now + proposal_first_min*60`）、`{type:"answer_proposal", id, accept: bool}`

**规则：**
- `phase == "adopting"` 时 `advance` 不推进任何系统（时间不走）
- 未婚且在世的成年人只有一位时，到 `next_proposal_at` 来一桩提亲（对象性别与当家人相反，年龄在 `adopt_age` 区间，`savings` 在 `[0, start_money]`），发 `proposal_arrived`；同时最多挂一桩。下一桩的时间：被拒绝后排到 `proposal_after_decline_min` 之后（只对头一次拒绝生效），其余情况（过期、第二次起的拒绝）排到 `proposal_interval_hours` 之后
- 过期（`proposal_ttl_hours`）作废，发 `proposal_expired`，无惩罚
- 接受：对象入住，沿用当家人的姓，`money += savings`，`married = true`，清空 `proposals`，发 `married`；之后不再来提亲
- 拒绝：移除该提亲
- `phase == "over"` 后，指令 `{type:"reroll"}` 把世界重置回 `"adopting"`（钱、物件、已建房间保留，人清空）

**《起家》第 1 期内容**（架空古代，全部原创文案，不出现参考游戏的任何词句）：
- needs：`fed 饱腹`、`energy 精神`、`happy 心绪`、`health 身子`
- rooms：`hall 堂屋`（built）、`side 厢房`（未建）、`yard 院子`（built，outdoor）
- objects 不少于 8 种：灶台、土炕、书案、织机、水缸、矮凳、鸡笼（outdoor）、菜畦（outdoor）
- livelihoods 一条：`reading 读书`，三级（蒙童、童生、秀才）
- items：米面（库存 food）、至少两种药各治一种病、至少一种哄人开心的东西（糖人之类）
- illnesses 两种；messes 两种（一室内一室外）；collectibles 三种；goals 不少于 5 条，其中有"把屋子收拾干净"
- **actions 不少于 20 条**，三类都要有：过日子的不少于 8 条、出状况的不少于 4 条（`requires` 为 `sick` 或 `need_below`）、有趣味的不少于 6 条（`base > 0`，不靠状态缺口驱动）；每条的 `label` 是底栏显示的那一句，如"在灶前偷嘴"

**照看者策略**（每模拟 1 小时执行一次）：领养第一位候选人；有提亲就接受；库存 food 少于 3 且钱够就买米面；有人病了且钱够就买对的药并使用；有人 `happy` 低于 30 且钱够就买哄人的东西并使用。不拖人、不赏罚、不买家具（开局摆好该包每种物件各一件）。
