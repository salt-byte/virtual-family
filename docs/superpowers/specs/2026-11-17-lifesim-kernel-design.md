## 1. 要做什么，为什么

雨蝶想自己做一款游戏：玩法照 Virtual Families 3 的路子，题材是中国古代家庭，一家人几代人从茅舍住进侯府。做的过程中把做法沉淀成一个 Claude Code 插件，以后用它**批量**做同类游戏。

"批量"决定了形态。这类游戏换个题材，底层系统几乎不变（小人照样会饿、会干活、会成家、会老去），变的是名字、数值和图。所以做成三层：

- **内核**：一个 Godot 项目，每款游戏都一样
- **主题包**：每款游戏一份，全是数据和素材
- **插件**：一组 skill，带人把一个主题包从题材做到发布

做的顺序是"先做游戏"：《起家》是主题包一号，从第一天起就把内核和内容分开放。游戏做完，内核和流程已经在那里，沉淀成插件是打包。

### 核心是什么（雨蝶的原话整理）

> 小人有自己的生活，会生病、会不开心；我们主要是用金币给他们解决问题；家里脏了要收拾；还有装修家里，包括扩充。

所以核心循环是四件事，其他系统都是为它供血的：

1. **小人自己过日子**，并且会出状况（饿、病、不开心）
2. **玩家花钱解决问题**（买吃的、买药、买让人高兴的东西）
3. **收拾家**（脏了、乱了、坏了）
4. **装修和扩建**（买家具摆起来、加房间、换更大的房子）——钱最大的去处，也是玩家看得见的成果

**金币的来路**（雨蝶说的）：

- **两口子的职业**：每天自动多一点钱；玩家把他们拖去干活，挣得更多
- **院子里掉落的东西**：捡起来卖钱
- **奖励**：做成某件事给一笔，比如把屋子收拾干净

**金币的去处**：照顾病人、让小人开心、买家具、装修和扩建。

**一局怎么开始**：领养一个人 → 媒人介绍对象、成亲 → 生孩子 → 孩子接手，一代代往下。

**职业不只是挣钱**：读书科举、从军这些路，除了收入还带来门第，是往上爬的路（见第 7 节）。

**操作**：小人可以拖动，拖到某样东西跟前他就去用它（拖到电视前就看电视）；不拖的时候他们过自己的日子。

以上这一整圈——挣钱、花钱、收拾、装修、拖动、自己过日子——就是第 1 期要做出来的东西。一代代怎么传（家庭）、怎么换更大的房子（家业阶梯和门第）、职业怎么分出四条路，排在它之后。**先把这一圈做到好玩，再加别的。**

## 2. 目标、不做的、绝不能出现的

**目标**

1. 《起家》网页版可玩：发一个链接就能玩，能连续玩过至少三代人，能从茅舍升到侯府
2. 内核不含任何题材专用的东西：换一个主题包，不改内核代码就能跑出另一款游戏
3. 插件能带着一个没参与过本项目的人，从"我想做某某题材"做到一款可发布的游戏

**这次不做**

- 自由画墙搭房子（每级家业一张设计好的图）。**装修是要做的**：买家具、在房间里自由摆放和挪动、换地面墙面、花钱加盖预留好位置的房间
- 其他家族作为要管理或对抗的对手（只在事件和婚配里出现）
- 手机打包、内购、广告、联机、云存档
- 防止玩家改系统时钟作弊
- 回头给 RPG 插件抽通用底座（已记下，另一件事）

**绝不能出现**

- **复刻参考游戏**：它的名字、小人形象、房屋和界面长相、事件文案、收集品和谜题内容，一样都不搬。只借玩法机制
- **做成报表游戏**：玩家看到的必须是小人在过日子，数值藏在后面。这是和《吾今有世家》一类的分界线
- **内核里出现古代专用词**："科举""侯府"只能出现在主题包里
- **离开几天回来全家死光**：见 5.3

## 3. 约束

- 引擎 Godot 4（本机已装 4.7.2），GDScript。和 RPG 插件一致，已有做法能接着用
- 先出网页版，只做电脑浏览器（横屏、鼠标），存档放在浏览器本地。拖拽等操作不要写成只认鼠标的死路，方便以后加触摸，但这次不做手机适配
- 玩法是"照看"不是"操控"：小人自己拿主意，玩家只能拖、赏、罚、买
- 画面是固定角度的斜俯视，一屏看到整栋房子的大部分，和这个类型的惯例一致；白盒阶段就按这个角度做
- 美术走哪条路线（AI 生图、开源素材、自己上传）和预算，留到第 5 期开始前的停靠点再定

## 4. 考虑过的做法

| | 做法 | 取舍 |
|---|---|---|
| A | 先手工做完一款，再回头总结成插件 | 第一款最快；但代码为这一款而写，第二款基本重做 |
| **B** | **通用内核 + 主题包，插件带人填主题包** | **第二款起只做内容和美术；代价是前期要把内核和内容切干净，批量出来的游戏骨架相同** |
| C | 纯流程插件，每款让 agent 从零生成（RPG 插件的形态） | 每款可以很不一样；但每款都是完整开发成本，和批量相悖 |

**雨蝶选了 B，按 A 的顺序做。** RPG 插件没走 B，是因为 RPG 每款的差异在玩法骨架上，成本大头又是剧情内容；生活模拟反过来。

## 5. 内核

### 5.1 两层：模拟层和画面层

```
画面层   房屋场景 · 小人动画 · 拖拽 · 界面 · "离开期间"小结
           ↑ 只读状态、接收事件        ↓ 只发玩家指令
模拟层   时钟 · 小人 · 自主行为 · 营生 · 家庭 · 家业阶梯 · 门第
         经济 · 事件 · 收集与目标 · 存档
```

**模拟层不依赖画面，可以无画面运行。** 它是一组纯逻辑的类，不继承场景节点；随机数用可指定的种子。这一条换来三样东西：

- 离线补算：回来时把离开的时间无画面快进一遍
- 自动测试：命令行里几秒钟跑完三十代
- 数值调整：批量跑几百个家族看分布

画面层对模拟层只做两件事：读状态来画，把玩家操作变成指令发下去。小人走到物件旁的动画属于画面层；模拟层只知道"某人正在用某物件，还剩多少时间"。

### 5.2 两个钟

这类游戏的节奏靠两个各走各的钟：

- **作息钟**跟设备时间走。现实里天黑了，游戏里也天黑，小人去睡觉。状态（饱腹、精力等）按现实时间涨落
- **年岁钟**按主题包里的"现实多少小时算一岁"推进，默认 2 小时。年龄、季节、几年一次的大事都挂在它上面

按默认值，一个季节 30 分钟，一代人从成年到寿终约四到六天。《起家》里庄稼按季节熟，考试按年份开。

### 5.3 离线补算

打开游戏时，算出离开了多久，用和在线时**同一套规则**快进，不播动画。规则：

- 最多补算 48 个现实小时（主题包可调），再久也按 48 小时算
- 离线期间，照看不周不会死人：状态最低掉到"虚弱"为止。寿终可以在离线时发生
- 需要玩家拿主意的事（选继承人、回应提亲、事件抉择）排队等玩家回来，不替玩家决定
- 补算完给一页"离开期间"小结：谁长了几岁、挣了多少、出了什么事

**排队期间时间照走**，在线离线同一套规则，游戏不为此暂停：

- 当家人去世、继承人未选：家里还有成年人就照常过日子、照常有收入，由在世的配偶或最年长的成年人暂代当家。家里一个成年人都不剩时，模拟冻结，直到玩家选定继承人
- 提亲和事件抉择各有期限（主题包定），过期作废，记进小结；作废不带惩罚

### 5.4 各模块

**小人。** 属性：姓名、性别、年龄、年龄阶段、营生及等级、喜好和厌恶、想不想要孩子、天资（每条营生路线一个值）。状态条的种类和涨落速度由主题包定义，内核不写死是哪几条。年龄阶段（幼儿、孩童、成年、老年）的岁数边界由主题包定。

**自主行为。** 小人闲下来时，看遍屋里可用的物件，给每个可做的事打分，按分数加一点随机挑一个去做：

> 分数 = 这件事能补上的状态缺口 × 习惯权重 × 喜恶修正 × 时段修正

每个物件在主题包里写明"我提供哪些事，每件事改变哪些状态、花多久、谁能做"。小人不认识灶台和书案，只认识"这东西能让饱腹涨四十"。

**行为表是这类游戏最核心的内容**（雨蝶点明的）。玩家大部分时间在看小人自己做事，所以"小人会做哪些事、什么时候做、做起来什么样"决定了游戏好不好看。主题包里每一条行为要写全：

- 在哪做（哪个物件，或不需要物件）、谁能做（年龄阶段、营生、喜恶）
- 什么时候想做（补哪个状态、什么时段、什么季节、心情如何时）
- 做多久、做完改变什么（状态、进度、钱、弄脏了什么）
- 画面上什么样（动作、底栏显示的那一句"正在做什么"）
- 能不能被赏罚

行为分三类，都要有：**过日子的**（吃、睡、洗、干活）、**出状况的**（生病时咳嗽卧床、不开心时发呆摔东西、偷懒）、**有趣味的**（追鸡、逗孩子、对月吟诗——不补什么状态，纯粹让人物活起来，也是赏罚的对象）。第三类最容易被省掉，却是"他们有自己的生活"这个感觉的来源。

行为不靠写死的日程表编排，而是靠上面的打分自然冒出来；我们编排的是行为表本身和它的条件。白盒阶段至少要有二十来条行为，才看得出一家人是不是"活的"。

**玩家指令。** 拖小人到物件上：让他立刻做那件事。表扬或批评：把这个小人对"刚做的那件事"的习惯权重调高或调低，有上下限，批评只是降低频率，不能禁止。捡收集品。买东西。除此之外玩家管不了小人：不能逼睡觉，不能逼把活干完。

**营生。** 若干条路线，每条一张等级表（名称、升级所需进度、收入、带来的门第）。小人在对应工位上做事攒进度，进度速度受天资影响。收入按时间到账。除此之外，营生还有四样通用能力，每条路线、每一级都可以单独开关，全由数据驱动：

- **关卡**：到了这一级不自动升，要等一场定期举行的考核，成败看进度和天资加运气。《起家》的科举用它
- **按季节结算**：收入不是匀速到账，而是在指定季节一次结清。务农用它
- **产业**：可以花钱买的份额（田、铺面），每份按比例放大这条路线的收入，跨代继承。务农和经商用它
- **风险**：每隔一段时间有一定概率出事（受伤或身亡），概率和后果由等级表定。从军用它

爵位不是单独的系统，就是营生等级带来的门第。

**家庭。** 婚配：定期有人上门提亲，一次给几位候选人，各带属性和门第；玩家选或拒。配偶搬进来，财产合并。生育：把夫妻拖到一起尝试，成功率随年龄和健康下降，有人数上限。孩子成年后：留下一位做继承人，其余离家（《起家》里是出嫁或分家），离家时按主题包规则花钱或得好处。当家人去世后玩家选继承人开下一代；没有孩子则这一局结束。

**家业阶梯。** 若干级，每级包含：一张房屋图、可用房间、解锁的物件和营生、升级条件（钱和门第）。升级就是换图加解锁。房屋里有修缮点（花钱或花工夫修好后解锁房间）和杂务（定期冒出来，小人自己会做，也可以拖人去做）。主题包可以只设一级，等于关掉这个系统。

**门第。** 钱之外的第二种资源，一个整数等级，各级名称由主题包定。来源：营生等级、婚配、事件。主题包可以关掉。

**会衰减。** 门第分两部分：当家人自己挣来的，和祖上传下来的。换代时，上一代的门第变成"祖荫"传给新当家，但打折（《起家》里的"爵位隔代降等"就是这条规则，不另设）。新当家有一段宽限期（主题包定，默认到 35 岁）靠祖荫撑着；宽限期一过，门第按"自己挣的"和"打折后的祖荫"里较高的算。

**门第撑不住家业时**：先给一次警告和一段补救时间；仍然不够，家业降一级——换回上一级的房屋图，放不下的物件收进库房不丢失，修好的房间再升回来时不用重修。

"守住三代"在《起家》里是一个目标（达成有奖励和成就），不是结局；游戏没有通关画面，玩到家里断了后为止。

**经济。** 一种货币。商店按类别卖东西，类别和货品由主题包定；其中一类是每天轮换的集市。食物是消耗品，吃完小人会挨饿。

**事件。** 一张事件表：触发条件（年岁、季节、家业等级、门第、家里有什么人）、文字、若干选项、每个选项的后果。疾病是一类特殊事件：给小人挂一个症状，症状持续扣健康，直到用对了药。

**收集与目标。** 收集品在屋外随机出现，不捡就消失，可以卖钱或凑成套。目标是一张清单，达成给一次性奖励。成就跨代保留。

**存档。** 整个模拟层状态存成一份带版本号的文件，另存最后在线时刻。每次有要紧变化和定时各存一次。

### 5.5 界面骨架

看过参考游戏的截图后定的信息安排（只借"放什么信息"，长相、配色、图标全部自己做）：

```
┌──────────────────────────────────────────────┐
│ [罚][赏]                                        │
│                                              │
│            房屋场景（斜俯视，可拖动平移）          │
│            小人在里面走动，可以拖                 │
│                                              │
│ ┌──────────────────────────────────────────┐ │
│ │ 头像  姓名 年岁 │ 正在做什么      │ 状态     │ │
│ │       营生     │ [家谱] [集市] [账房] │ 银钱 │ │
│ └──────────────────────────────────────────┘ │
└──────────────────────────────────────────────┘
```

- 屏幕绝大部分留给房屋，界面只占底部一条和左上角两个按钮
- 底部条显示当前选中小人：姓名、年岁、营生、**正在做什么**（一句话）、状态（一句话，如"有点饿"），点开才看到状态条
- 详细信息、商店、摆家具都是弹出面板，关掉就回到看房子

《起家》里底部条做成一条案几或卷轴的样子，按钮是家谱、集市、账房。

### 5.6 内核怎么认主题包

内核启动时读一个主题包目录，先照格式检查一遍，有错就报出是哪张表哪一行，不启动。内核代码里出现的词只有"状态条""营生""家业等级""门第"这类通用词。

**从第一天起就留一个"试验主题包"**：现代题材、极小（一级家业、两条营生、三个物件、两个事件）。它不是游戏，是用来防止内核悄悄长出古代专用逻辑的——每次改内核，两个主题包的自动测试都要过。

## 6. 主题包

一个目录，大致是：

```
packs/qijia/
  pack.json        名称、年岁钟速度、离线上限、年龄阶段、开关
  needs.json       状态条
  objects.json     物件及其提供的事
  livelihoods.json 营生路线和等级
  estate.json      家业阶梯
  standing.json    门第等级
  shop.json        商店类别和货品
  events.json      事件和疾病
  collectibles.json / goals.json
  names.json       姓名库
  text/            界面和事件文案
  art/             房屋图、小人、物件、界面
```

数据用 JSON：agent 好填，好做格式检查。具体字段留给建造者定。

## 7. 第一款：《起家》

架空朝代，不绑定真实历史。

**家业六级**：茅舍 → 瓦房小院 → 二进宅院 → 大宅 → 官邸 → 侯府。

**四条营生**（雨蝶确认过方向）：

| 路线 | 味道 | 等级示意 |
|---|---|---|
| 读书 | 慢、花钱，一朝得中门第飞升；有考试关卡 | 蒙童 → 童生 → 秀才 → 举人 → 进士 → 入仕 |
| 经商 | 来钱快，门第低 | 货郎 → 摊主 → 掌柜 → 东家 → 巨贾 |
| 务农 | 稳，按季节收成，靠置地扩大 | 佃户 → 自耕 → 富农 → 地主 |
| 从军 | 险，可能战死；军功封爵，侯府主要从这里来 | 兵卒 → 什长 → 校尉 → 将军 → 封侯 |

孩子的天资决定适合哪条路。婚配能抬门第。

**换皮对应**：工位是书案、灶台、织机、田地、演武场；提亲由媒人上门；事件由邻里传话和官府告示带来；病看症状抓方子；集市就是集市。

**爬到顶之后**：《吾今有世家》的玩家抱怨到顶之后只剩重复。《起家》的回应是守业比创业难——门第会衰减，爵位隔代降等，子孙不成器家道就中落。住进侯府不是结局，守住三代才算。

**男女分工（雨蝶已定）**：架空朝代里，男女都能走任意一条营生路线，也都能当家；婚配可以娶进来也可以招赘。内核不为性别写特殊规则。

## 8. 插件

暂名 AI Life-Sim Studio。里面有：

- **内核**的完整拷贝，新游戏开工时复制出来
- **主题包模板**和格式检查脚本
- **新 skill**：制作人（接需求、排步骤、定停靠点）、题材定位、**行为编排**（写行为表，插件里分量最重的一个）、状态与物件、营生设计、家庭与代际、家业阶梯与门第、事件写作、数值调整（用无画面批量跑）、内核使用说明
- **从 RPG 插件拷过来改的 skill**：美术方向、三条素材路线、画风统一、界面布局、文风、自动试玩、网页发布、开发日志。直接拷贝而不是引用，因为插件之间没法互相依赖

插件的流程在《起家》做完之后定稿，按实际走通的步骤写，不凭空设计。

## 9. 分期

| 期 | 做什么 | 做完能看到什么 |
|---|---|---|
| 0 | 模拟层骨架：两个钟、小人、状态、自主行为、钱、存档、离线补算；试验主题包 | 命令行里跑一个小人过完一生，测试全过 |
| 1 | **核心循环白盒**：一间屋、色块小人自己过日子；会饿、会病、会不开心；商店买吃的和药；杂务（脏、乱、坏）；买家具摆放；加一间房；拖拽、赏罚；"离开期间"小结。金币三条来路都要有：两口子各一份职业（每天自动到账，拖去工位干活挣得更多，先只做一条路线、两三级）、院子里掉落物捡了卖钱、几个带奖励的目标（如"把屋子收拾干净"）。开局是**领养一个人**（从几位候选人里挑，各带年岁、职业、喜恶，不满意可以换一位）；过一阵媒人上门介绍对象，成亲后配偶带着自己的职业搬进来。生孩子放第 2 期 | **停靠点：雨蝶亲手玩，判断这一圈好不好玩** |

| 4 | 事件、更多疾病、成套的收集品、完整的目标清单 | 内容完整的白盒 |

第 1 期的停靠点最要紧：它只包含雨蝶说的核心四件事。如果这四件事用色块玩着没意思，后面都要重想，不该往下堆内容。

## 10. 怎么算做对了

- 模拟层每个模块有自动测试；两个主题包都要过
- 无画面跑三十代：不会全家饿死，钱不会多到没处花，至少有一部分家族能爬到顶、也有一部分中落
- 离线补算和在线跑同样长的时间，结果在可接受的误差内一致
- 换主题包不改内核代码
- 雨蝶在第 1 期和第 5 期亲手玩过并认可

## 12b. 对照参考游戏官方帮助中心后的修订（11-17）

初稿只参考了玩家攻略。读了开发商帮助中心的六篇文章后，补上和改掉这些（只借规则，文案和名目全部自己写）：

**进第 1 期的**

1. **状态用词语阶梯显示**，不是进度条。每条状态在主题包里配一串"低于多少显示什么词"（心绪：舒心 → 有点闷 → 郁结；身子：康健 → 虚弱 → 极虚）。底栏显示的就是这个词
2. **病要先看症状再抓药**。病人不会头顶写着病名：他会时不时做出症状动作（咳嗽、挠痒、捂肚子），玩家认出来，买对应的药。每种病在主题包里配一条症状行为
3. **夸奖本身影响心绪和干活**。久不夸奖，心绪慢慢掉；夸了涨一点。短时间里连着夸太多次，小人会烦，夸奖暂时失效
4. **病着、饿着不长营生进度**。干活照干，进度不涨
5. **工钱按时辰分批到账**：一天的工钱分成 24 份，每小时到一份，不干活也有；干活另有零钱
6. **提亲的节奏**：入住后 15 分钟内来第一桩；拒了之后 45 分钟来下一桩；此后每 24 小时一桩
7. **掉落物**：每种第一次捡到的收进收藏，不给钱；重复的才卖钱

**进后面几期的**

8. **故障分两档**（第 4 期）：小故障（屋漏、灶堵）要一个 14 岁以上的人拿着工具自己修；大故障（走水之后、梁坏了）要花钱请匠人。故障没修好时，全家人心神不宁，不干正事
9. **雇人**（第 4 期）：帮佣和花匠，雇了之后大约每小时来一趟
10. **孩子**（第 2 期）：孩子没有营生，但能做杂务和捡东西；14 岁起能修东西；19 岁离家
11. **继承**（第 2 期）：房子、家具、存款、收藏、目标进度都传下去
12. **营生工位可以升级**（第 3 期）：升级后进度涨得快；夫妻同用一个工位，一份升级两人受益。这是金币的重要去处
13. **心绪的其他来源**（第 2、4 期）：想要孩子却没有会郁结；家人去世会难过一阵；添置家具、屋子干净会舒心
14. **昼夜颠倒开关**（白盒画面那份计划）：给夜里才有空玩的人，把游戏里的昼夜和现实反过来

**有意和参考游戏不同的**

- 参考游戏里孩子成年后职业是随机的，玩家不能培养；《起家》里孩子的路可以从小培养（读书、习武），这是"几代人往上爬"的核心
- 参考游戏的房间按代数解锁；《起家》按家业等级和门第解锁
- 参考游戏离线时会饿坏累坏；《起家》离线时照看不周不致死

官方资料没有说的：年岁增长速度、寿命、人怎么会死。这几项仍按玩家攻略的量级和我们自己的设定。
